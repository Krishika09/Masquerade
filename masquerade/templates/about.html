Methodology

How Masquerade reaches a verdict

Malware imitates legitimate files, but attackers control file names, section labels and import tables independently of the code. A disguised file therefore shows inconsistencies in its own structure. Masquerade asks whether a PE file's properties agree with each other and with its claimed identity, instead of judging each feature on its own - and it shows every verdict as named, scored evidence an analyst can verify.

SAFETY
Static analysis only. Uploaded files are read as bytes and parsed with pefile. They are never executed, loaded as libraries or passed to a subprocess, and are stored with a neutral .sample suffix. Dynamic validation (Ghidra, Procmon, Wireshark in an isolated VM) is a separate, manual step outside this tool.

Every finding carries the same record: name, category, severity (LOW / MEDIUM / HIGH), score, raw evidence, a plain-language explanation and a "why" rationale, plus a MITRE ATT&CK reference where one applies. The same record drives the score, the report and later validation.

Severity scales a finding's weight: HIGH × 1.0, MEDIUM × 0.6, LOW × 0.3. In each bucket the strongest finding counts in full and every additional finding adds 25 % of its value, capped at the bucket weight so repeated evidence of the same kind cannot dominate. The final score is round(100 × Σ points / {{ buckets.values()|sum(attribute='weight') }}). Levels: LOW 0–29 MEDIUM 30–59 HIGH 60–79 CRITICAL 80–100.

By design a single strong signal (e.g. high entropy alone) keeps a file LOW or MEDIUM; the score climbs only when independent categories of contradiction agree. The weights are initial values intended to be tuned on a validation set - they are not claimed to be optimal.

Machine learning and calibration

A Random Forest is trained on 24 features: 15 conventional PE features (size, entropy, import/string counts, signature, overlay…) and 9 contradiction features (per-category severity, RWX count, unusual entry point, number of findings). The forest is fit on the 70 % training split; CalibratedClassifierCV with Platt (sigmoid) scaling is fit on the 15 % validation split; Brier score, expected calibration error and a reliability diagram are measured on the untouched 15 % test split.

A raw forest score is the share of tree votes, not a probability. The report therefore shows both, and only the calibrated value is reported as a malware probability. Rule evidence and the model run side by side; the model does not override the explainable score.

Demo data disclosure: this prototype ships without a malware corpus. The model is trained on a reproducible synthetic feature table (see Model & Calibration). Its metrics demonstrate the workflow only and do not represent real-world detection performance.

Limitations

  • Static analysis cannot see run-time behaviour; heavily packed files reveal little until unpacked.
  • Rules are heuristics: installers, game protectors, JIT runtimes and security tools can trigger them.
  • Signature presence is detected but not cryptographically verified.
  • The bundled ML model is trained on synthetic data; weights and thresholds need tuning on a real, de-duplicated corpus.
